## 🐙 GitHub Releases 发布

GitHub Releases 提供各平台的可执行文件，用户无需安装 Python 环境。

### 自动化发布流程

#### 触发条件

当满足以下条件时，GitHub Actions 会自动构建并发布：

1. **推送代码到 main/master 分支** → 运行 CI 测试
2. **创建版本标签**（如 `v2.0.4`）→ 构建所有平台并发布到 Releases

#### 工作流程详解

```
推送代码/打标签
    ↓

│   - Windows + Python 3.9-3.12   │
│   - macOS + Python 3.9-3.12     │
│   - 验证依赖导入和功能测试       │
└─────────────────────────────────┘
    ↓ (仅当打tag时)
┌─────────────────────────────────┐
│   Build Releases                │
│   (build-releases.yml)          │
├─────────────────────────────────┤
│ 🐧 Linux (Ubuntu Latest)       │
│   → linux_LabelCraft_v2.0.4.tar.gz

│ 🪟 Windows (Windows Latest)    │

└─────────────────────────────────┘
    ↓
上传到 GitHub Releases
```

### 手动发布步骤

#### Step 1: 更新版本号

编辑 [`libs/__init__.py`](../libs/__init__.py)：

```python
__version_info__ = ('2', '0', '4')  # 修改版本号
__version__ = '.'.join(__version_info__)
```

**版本号规范**（遵循[语义化版本](https://semver.org/lang/zh-CN/)）：
- **主版本号 (MAJOR)**：不兼容的 API 修改（如 `v1.x.x` → `v2.0.0`）
- **次版本号 (MINOR)**：向下兼容的功能性新增（如 `v2.0.x` → `v2.1.0`）
- **修订版本号 (PATCH)**：向下兼容的问题修正（如 `v2.0.3` → `v2.0.4`）

#### Step 2: 提交代码并创建标签

```bash
# 1. 添加所有修改的文件
git add -A

# 2. 提交代码（编写清晰的提交信息）
git commit -m "Release v2.0.4: Fix i18n locales directory

- Move locales to libs package for proper wheel inclusion
- Update I18nEngine path resolution
- Ensure translation files are included in distribution"

# 3. 创建版本标签（使用 annotated tag）
git tag -a v2.0.4 -m "Version 2.0.4 - Fix i18n: Move locales to libs package"

# 4. 推送到 GitHub
git push origin main
git push origin v2.0.4
```

**标签命名规范**：
- 格式：`v主版本.次版本.修订版本`
- 示例：`v2.0.4`、`v2.1.0`、`v3.0.0`
- 标签消息应简要描述本次更新的主要内容

#### Step 3: 等待 GitHub Actions 自动处理

访问：`https://github.com/syd168/LabelCraft/actions`

你会看到：
- ✅ **CI Tests** 运行中...（测试多平台兼容性）
- 🏗️ **Build Releases** 运行中...（构建各平台安装包）

构建完成后，访问 Releases 页面查看：
`https://github.com/syd168/LabelCraft/releases/tag/v2.0.4`

## 🐍 PyPI 发布

PyPI 发布允许用户通过 `pip install labelcraft` 安装。

### 前置准备

#### 1. 注册 PyPI 账号

访问 https://pypi.org/ 注册账号。

#### 2. 获取 API Token

1. 访问 https://pypi.org/manage/account/token/
2. 点击 **"Add API token"**
3. 填写：
   - **Token name**: `LabelCraft Release Token`
   - **Scope**: `Entire account` 或特定项目
4. 点击 **"Create token"**
5. **立即复制 token**（只显示一次！）
   - 格式：`pypi-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

#### 3. 配置 Token

**方法一：命令行参数（临时）**

```bash
twine upload --username __token__ --password pypi-xxx dist/*
```

**方法二：配置文件（推荐）**

创建 `~/.pypirc` 文件：

```ini
[distutils]
index-servers =
    pypi
    testpypi

[pypi]
repository = https://upload.pypi.org/legacy/
username = __token__
password = pypi-你的token

[testpypi]
repository = https://test.pypi.org/legacy/
username = __token__
password = pypi-你的测试token
```

设置权限：
```bash
chmod 600 ~/.pypirc
```

然后直接上传：
```bash
twine upload dist/*
```

**方法三：添加到 GitHub Secrets（用于自动发布）**

如果想让 GitHub Actions 自动发布到 PyPI：

```
GitHub仓库 → Settings → Secrets and variables → Actions
→ New repository secret

Name: PYPI_API_TOKEN
Value: pypi-你的token
```

### 本地构建和发布流程

虽然 GitHub Actions 可以自动发布，但推荐先在本地构建测试。

#### Step 1: 清理旧的构建文件

```bash
cd /home/syd168/workspace/MyNeuralNetwork-master/LabelCraft
rm -rf dist/ build/ *.egg-info
```

#### Step 2: 构建分发包

```bash
# 方法一：使用 setup.py
python setup.py sdist bdist_wheel

# 方法二：使用 build 模块（推荐）
pip install build
python -m build
```

这会生成两个文件：
- `dist/labelcraft-2.0.4-py2.py3-none-any.whl` (wheel 包)
- `dist/labelcraft-2.0.4.tar.gz` (源码包)

#### Step 3: 验证构建产物

```bash
# 检查生成的文件
ls -lh dist/

# 检查 wheel 包内容
unzip -l dist/labelcraft-2.0.4-py2.py3-none-any.whl

# 关键检查项：
# ✅ main.py
# ✅ labelcraft_ui.py
# ✅ libs/__init__.py
# ✅ libs/i18n_engine.py
# ✅ libs/locales/*.json (重要！)
# ✅ resources/icons/*
# ✅ data/*

# 检查 tar.gz 包内容
tar -tzf dist/labelcraft-2.0.4.tar.gz | head -30
```

**常见错误检查**：
- ❌ 缺少 `labelcraft_ui.py` → 导致 `ModuleNotFoundError`
- ❌ 缺少 `libs/locales/*.json` → 导致界面文字显示为 `[]`
- ❌ 缺少 `resources/icons/*` → 导致图标无法显示

#### Step 4: 上传到 TestPyPI（可选但推荐）

在正式发布前，先发布到 TestPyPI 进行测试：

```bash
# 上传到 TestPyPI
twine upload --repository testpypi dist/*

# 从 TestPyPI 安装测试
pip install --index-url https://test.pypi.org/simple/ labelcraft

# 验证功能
labelcraft --help
labelcraft  # 启动应用，检查界面是否正常
```

TestPyPI 地址：https://test.pypi.org/project/LabelCraft/

#### Step 5: 上传到 PyPI

```bash
# 方法一：使用 twine（推荐）
twine upload dist/*

# 方法二：使用 setup.py
python setup.py upload
```

上传成功后，访问：
`https://pypi.org/project/LabelCraft/2.0.4/`

#### Step 6: 验证发布结果

**检查 PyPI 页面**：
- ✅ 版本号正确
- ✅ 描述和 README 显示正常
- ✅ 下载链接可用
- ✅ 分类器（classifiers）正确

**测试安装**：

```bash
# 在新虚拟环境中测试
python -m venv test_env
source test_env/bin/activate  # Linux/macOS
# test_env\Scripts\activate   # Windows

# 安装
pip install labelcraft==2.0.4

# 验证安装
labelcraft --help
python -c "import libs; print(libs.__version__)"

# 启动应用
labelcraft
```

## ❓ 常见问题与故障排除

### 问题 1：安装后界面文字显示为 `[]`

**原因**：`locales` 目录未被包含在分发包中。

**解决**：
1. 确保 `libs/locales/` 目录存在且包含 `.json` 文件
2. 检查 `setup.py` 中的 `package_data` 配置：
   ```python
   package_data={
       '': ['locales/*.json'],
   },
   ```
3. 重新构建并验证：
   ```bash
   python -m zipfile -l dist/labelcraft-2.0.4-py2.py3-none-any.whl | grep locales
   ```

### 问题 2：`ModuleNotFoundError: No module named 'labelcraft_ui'`

**原因**：`labelcraft_ui.py` 未被包含在分发包中。

**解决**：
1. 检查 `setup.py` 中的 `py_modules`：
   ```python
   py_modules=['main', 'labelcraft_ui', 'resources'],
   ```
2. 重新构建并验证：
   ```bash
   python -m zipfile -l dist/labelcraft-2.0.4-py2.py3-none-any.whl | grep labelcraft_ui
   ```

### 问题 3：PyPI 上传失败 - "File already exists"

**原因**：PyPI 不允许覆盖已存在的版本。

**解决**：
1. 增加版本号（如 `2.0.4` → `2.0.5`）
2. 或者删除旧版本（需要在 PyPI 网站操作）
3. 重新构建并上传

### 问题 4：GitHub Actions 构建失败

**检查步骤**：
1. 访问 Actions 页面查看详细日志
2. 常见原因：
   - 依赖安装失败 → 检查 `requirements.txt`
   - 资源文件缺失 → 检查 `MANIFEST.in`
   - 权限问题 → 检查脚本执行权限

**调试技巧**：
```bash
# 在本地模拟 GitHub Actions 环境
docker run -it ubuntu:latest bash
# 然后在容器中执行构建脚本
```

### 问题 5：图标无法显示

**原因**：`resources` 目录未被正确包含。

**解决**：
1. 确保 `resources.qrc` 已编译为 `libs/resources.py`：
   ```bash
   pyside6-rcc resources.qrc -o libs/resources.py
   ```
2. 检查 `MANIFEST.in`：
   ```
   include resources.qrc
   recursive-include libs *
   ```
3. 重新构建

### 问题 6：深色/浅色模式颜色不正确

**原因**：使用了硬编码颜色而非 Qt palette。

**解决**：
参考项目记忆中的 UI 配色规范，使用 Qt palette 系统：
```python
palette = QApplication.palette()
color = palette.color(QPalette.ColorRole.Text)
```

### 🚀 自动化发布脚本

创建 `release.sh` 简化发布流程：

```bash
#!/bin/bash
set -e

VERSION=$1
if [ -z "$VERSION" ]; then
    echo "Usage: ./release.sh <version>"
    echo "Example: ./release.sh 2.0.4"
    exit 1
fi

echo "🚀 Releasing version $VERSION..."

# 1. 更新版本号
echo "📝 Updating version..."
sed -i "s/__version_info__ = .*/__version_info__ = ('${VERSION//./', '/}')/" libs/__init__.py

# 2. 提交
echo "💾 Committing changes..."
git add -A
git commit -m "Release v$VERSION"

# 3. 打标签
echo "🏷️  Creating tag..."
git tag -a v$VERSION -m "Version $VERSION"

# 4. 推送
echo "📤 Pushing to GitHub..."
git push origin main
git push origin v$VERSION

# 5. 构建
echo "🔨 Building packages..."
rm -rf dist/ build/ *.egg-info
python setup.py sdist bdist_wheel

# 6. 验证
echo "🔍 Verifying build..."
unzip -l dist/labelcraft-${VERSION}-*.whl | grep -E "(main|labelcraft_ui|locales)"

# 7. 上传到 PyPI
echo "📦 Uploading to PyPI..."
twine upload dist/labelcraft-${VERSION}*

echo "✅ Release $VERSION completed!"
echo "🌐 PyPI: https://pypi.org/project/LabelCraft/$VERSION/"
echo "🐙 GitHub: https://github.com/syd168/LabelCraft/releases/tag/v$VERSION"
```

使用方法：
```bash
chmod +x release.sh
./release.sh 2.0.4
```

### 📊 项目结构要点

**关键文件和目录**：

```
LabelCraft/
├── main.py                  # 入口文件（必须在 py_modules 中）
├── labelcraft_ui.py         # 主UI文件（必须在 py_modules 中）
├── setup.py                 # 打包配置
├── MANIFEST.in              # 包含文件列表
├── requirements.txt         # 运行时依赖
├── libs/
│   ├── __init__.py          # 版本号定义
│   ├── i18n_engine.py       # 国际化引擎
│   ├── resources.py         # 编译后的资源文件
│   ├── locales/             # 翻译文件（必须在包内）
│   │   ├── en.json
│   │   ├── zh-CN.json
│   │   └── ...
│   └── ...
├── resources/
│   ├── resources.qrc        # Qt 资源文件
│   └── icons/               # 图标文件
└── data/                    # 数据文件
```

**打包配置要点**：

1. **setup.py**：
   ```python
   py_modules=['main', 'labelcraft_ui', 'resources'],
   packages=find_packages(),
   package_data={'': ['locales/*.json']},
   include_package_data=True,
   ```

2. **MANIFEST.in**：
   ```
   include resources.qrc
   recursive-include libs *
   recursive-include resources *
   recursive-include data *
   ```

3. **I18nEngine 路径**：
   ```python
   # 正确：相对于当前文件
   locales_dir = os.path.join(os.path.dirname(__file__), 'locales')
   ```
